# デバイスIDとは

[English](device-id.en.md) | **日本語**

**デバイスIDは、「どのデバイスか」を識別するための、一意のID（UUID）です。**


## 何に使うのか

- **NetSyncなどの通信**：RPC（別の端末で処理を呼び出す仕組み）やメッセージのやり取りで、デバイスを識別する。
- **MDMによるデバイス管理**：端末の状態や配信・操作の対象を、個々のデバイスに結び付ける。
- **開発・運用の確認**：ログや管理画面のIDを照合し、どのデバイスで起きたことかを確認する。

端末名やIPアドレスが変わっても、保存されたIDが同じなら、同じデバイスとして扱うための基準になります。

## 基本の考え方

### 同じデバイスには、同じIDを使う

IDは初回に生成し、保存した値を使い続けます。アプリごと・起動ごと・接続ごとに作り直さず、同じデバイスを扱うアプリやサービスで共有します。Device ID Providerは、この生成・保存・取得を担います。

ただし、これは製造番号などのハードウェアに焼き付いた値ではありません。保存ファイルの削除や端末の初期化によって、IDが変わることがあります。

### 異なるデバイスには、異なるIDを使う

UUIDは、独立して生成したID同士が事実上重複しないようにするための形式です。ただし、**IDファイルをコピーすれば、別の端末でも同じIDになってしまいます。** 全端末を照合して重複を防ぐ仕組みではないため、端末の複製やバックアップの展開時にも、IDを重複させない運用が必要です。

## どこに保存されるのか

現在のDevice ID Providerでは、次の場所に保存します。

| 環境 | 保存場所と形式 |
| --- | --- |
| Android | 共有画像領域の `Pictures/Device-ID-Provider/<UUID>.png`。1×1ピクセルのPNG画像 |
| Windows | `%LOCALAPPDATA%\Styly\Device-ID-Provider\device.id`。UUIDを記録したテキストファイル |
| macOS | `~/Library/Application Support/Styly/Device-ID-Provider/device.id`。UUIDを記録したテキストファイル |
| Unity Editor（Windows・macOS） | 上記OSの `Device-ID-Provider` フォルダー内に、`<プロジェクトのパスから求めたハッシュ>/device.id` として保存 |

### Androidで画像として保存する理由

Androidの保存領域とアクセス権限の制約のもとで、複数のアプリが同じIDを参照できるよう、共有画像を扱う仕組み（MediaStore）を使っています。画像が残っていれば、アプリを再インストールしても同じIDを利用できます。

`UUID.png` という固定名ではなく、**実際のUUIDがファイル名**になります。たとえば `123e4567-e89b-42d3-a456-426614174000.png` です。IDは画像の絵柄ではなく、この名前に記録されています。

### PCとUnity Editorでの単位

Windows・macOSの通常のアプリでは、**OSユーザーごと**に保存します。同じPCでも、別のOSユーザーでは別のIDになります。

Unity Editorでは、複数のテスト環境を区別するため、**プロジェクトのパスごと**にIDを分けます。同じPC上でも別の場所にあるプロジェクトやクローンは別のIDになり、プロジェクトを移動するとIDが変わることがあります。

OSの保存先を取得できない場合は、Unityの `Application.persistentDataPath` を基点に保存します。この場合、通常の保存先とは共有範囲が異なることがあります。

## 運用で守ること

- **IDファイルを消したり、名前・内容を変えたりしない。**
- **別の端末へIDファイルをコピーしない。** 端末を複製する際は、複製元のIDを引き継がせないようにします。
- **IDを取得できないときは、権限やストレージの状態を確認する。** 別のIDを作って代用すると、同じ端末が別端末として扱われる原因になります。
- **初期化や端末交換の後は、実際のIDを確認する。** IDが変わった場合は、MDMの登録や通信先との対応も見直します。
